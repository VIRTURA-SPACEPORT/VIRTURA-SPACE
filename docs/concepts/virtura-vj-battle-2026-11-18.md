# VIRTURA VJ BATTLE — 线上赛事、空间入侵与自助式创作集会

> 记录日期：2026-11-18｜版本：Concept v0.1｜状态：长期产品提案，**未宣布活动、场地、奖金或报名开放**  
> 归属：VIRTURA Space 的独立赛事应用候选；VIRTURA Collective 负责未来真实活动的策划与主办。  
> 关联规划：[VIRTURA ID / Pass 与多端应用路线](./virtura-pass-and-distributed-apps-2026-11-18.md)

**后续关键修正（2026-11-18）**：现有现实游戏与线下 Battle 案例主要供活动组织参考，VIRTURA 的核心区别是线上参赛者、实体舞台和数字空间能够共同参与同一活动。SceneForge 不是赛事页面上的装饰，而是数字场地、预演、共享节目状态和赛后回放的基础能力。具体产品/接口/试点见 [VJ Battle × SceneForge 线上线下融合方案](./virtura-vj-battle-sceneforge-hybrid-2026-11-18.md)。其中参考 [Revision 2026 Shader Royale VJ Session](https://2026.revision-party.net/events/livecoding-events/) 的全球远程 VJ 实时参与实体舞台方案。

## 01. 创始想法（按提出时原意记录）

- 希望组织一场**大型 VJ Battle**：线上游戏式集会，连接实际比赛场地，并借鉴增强现实游戏／ARG（alternate reality game，现实与虚拟交织的活动）“入侵现实”的感受。
- 不是把上网课作为比赛门槛。比赛前提供**黑客松式知识分享、技能确认与可操作考验**：例如 BPM、相位、同步、输入输出、Cue、现场故障恢复。让参与者理解规则、完成练习、展示技能，建立适当的分组或赛制。
- 之后在选定线上或实体场地进行比赛，提供观看、评审、分组、获奖与后续作品归档。场地、奖金、奖品、评委、赞助等均未确定。
- 可以是赛事专属独立 Web App：**VIRTURA VJ BATTLE**（工作名）；也可能与 **VIRTURA Pass / VIRTURA ID** 打通。它应保有自己的视觉身份和游戏机制，而不是一个“VJ License 上网课页面”。
- 自助参与和自助展示也是关键方向：参赛者/创作者能够自己提交、练习、发布经审阅的成果、参加活动，形成可再次进入的数字文化空间。
- 未来微型入口可以分布在微信、小红书、移动 Web、桌面、XR 端；用户的主身份与授权资源应能够关联，不要求所有端使用一套原生前端代码。
- 需要研究每日资源访问额度、任务调度、场地与虚拟道具／档案关系，且控制用户注意力负担。
- 本提案不预设 NFT、链上积分、正式职业资格、赛事赌博或每天强制签到。

## 02. 产品定位与边界

**一句话**：一场能从浏览器入场、通过实战试做了解规则、带着个人 Pass 参赛、在实时视觉舞台上完成对抗、赛后保留作品与贡献的社区赛事。

四个子系统共享 ID 和内容档案，不应拆成四个同级公开 App：

| 子系统 | 参赛者的明确任务 | 真实结果 |
| --- | --- | --- |
| The Briefing / 战前简报 | 看规则、运行简短的 BPM / Cue 测试、了解设备要求 | 清楚知道如何参与，不自动获得职业认证 |
| The Lab / 试做与共享 | 运行 5–15 分钟练习或复现素材，上传演示 | 有版本号的试做成果与自愿反馈 |
| The Arena / 赛场 | 报名分组、参加直播/异步预选、观看比赛与评分 | 经过规则说明的赛事结果与演出记录 |
| The Archive / 赛后馆藏 | 回看参赛版本、作者与素材说明、现场录屏 | 可访问且尊重授权的作品与经验档案 |

主产品为赛事；Academy 只提供赛前必要知识和后续深化训练，不把备赛伪装成漫长在线课程。用户也可以只做观众、只看作品或只参与 Jam，不强制参赛。

## 03. 从零进入赛事：首次用户的通关流程

0. 从公开海报/作品/好友分享进入**本届活动页**：看到“玩法、开放状态、支持设备、下一个动作”，无需登录阅读。
1. 选择“参赛 / 看比赛 / 加入共同创作”。只在提交或保存时要求 ID；受邀内测按现有授权策略。
2. 参赛者阅读 **3–5 张规则卡**：BPM 与节奏/相位差异、音画时间结构、现场交接、素材许可与发布限制、故障兜底。
3. 完成**一项可复现的小练习**，例如依据 120 BPM 设置循环并处理一次外部同步中断。保留参考答案和跳过/申诉通道，不靠记忆选择题替代实操。
4. 通过技术自检：能否从约定音频/视频输入产生符合基线的可播放结果；系统明确写出推荐环境与限制。
5. 进入对应**赛组/赛道**，提交一段 30–60 秒试赛内容；赛组由公开标准与人工复核决定，既有职业经历可申请直接接受对应实操验证，不强制先听课。
6. 比赛日按赛制参加：资格赛/主题创作/现场对抗，舞台倒计时、回放和主持人说明。失败时提供替代上传/回放规则，避免网络差导致不公平淘汰。
7. 赛后在 Pass 留下**参赛经历**和经授权发布的作品链接。比赛成绩、参与纪念、技能评估、团队成员资格与项目工作权限互不自动等价。

## 04. 赛道不是单一“驾照等级”

借鉴现有 VIRTURA 技能图谱 COPY / MODIFY / COMPOSE / COLLAB / PERFORM，可作为学习记录的证据；**赛事组别**独立定义，以避免“高分=准许现场工作”的误解。

第一届候选，待实际报名与评委产能确认：
- **Open Jam**：不限资历，非淘汰，重视参与与作品分享；适合新人、跨学科与合作。
- **Visual Performance**：围绕音乐段落、BPM 相位、收放、素材切换及技术恢复进行实时编排；可以使用现有 VJ 软件/视频系统。
- **Live Systems / Code**：以 Shader/WebGL/实时控制器/自制系统为媒介，考察响应、输入、可解释的实时性与创意，不强制工具统一。
- **Spatial / XR Wildcard**：空间视觉、手势、AR/MR、现场互动与实体场域相连；可在硬件具备时增设，不作为所有人的入场义务。

若规模不足，首届只做 Open Jam + 一条主赛道，不为热闹虚构四个完整赛区。

### 初步赛制（可验证的三阶段）

- **Qualifier（异步）**：开放统一音轨或节拍数据，提交 45–60 秒演示和参数/工具说明。评审双盲不可完全保证；至少应避免熟人优待并公布评分规则。
- **Jam（协作）**：围绕限定主题/共用素材包，在固定窗口内自由创作，可自行组成队伍。不是必须拿奖的比赛，解决不同经验水平都能参与的问题。
- **Battle（现场或同步线上）**：2 人/2 组对抗，统一节目长度、媒体规格与控制窗口，由主持人播报。技术故障、缺席、超时与替换提交有预先公开的规则。

初步评分建议：表达与音乐判断 35、实时控制/结构 25、可靠性/应变 25、合作与说明 15。赛事评分和能力验证应独立；即使获胜也不等于全面技能认证。分数与权重需赛前公开并通过测试赛校准。观众投票只占明确一部分，防止刷票左右结果；奖项/奖金需预算、版权、税费及条款确认后宣布。

## 05. “入侵现实”：ARG / 线下节点如何工作

这是**经场地方授权的游戏化空间叙事**，不是对公众空间或他人设备的实际入侵。

- 线上赛场显示若干“信号节点”，每个节点对应场馆的特定屏幕、声音、表演或已获准设置的实体牌；参赛作品可以点亮节点/接管一段比赛时隙。
- 现场观众扫描活动标识进入一个**只影响活动内状态**的交互（例如选取声音轨、触发合法视觉 Cue、决定下一轮主题），必须经舞台导演最终审查，不允许公众直接操作真实播控或高功率设备。
- 远程观众通过 Web 输入贡献少量变量/投票，比赛将这些输入映射为有边界的视觉变化；远程输入有速率限制和延迟兜底。
- XR 端是加强版观看与交互方式，手机 2D 页面始终有完整替代路径；不要求 GPS 常开、全天候定位、接触陌生人或在道路上寻找隐藏节点。
- 某届赛事可以在某个正式场地结束，但作品档案和赛制可进入下届活动。**活动不应变成长期强迫打卡游戏**。

## 06. 日常资源额度：建议的是“创作配额”，不是付费能量币

每日配额**目前仅为研究方案**，不开放兑换、不宣称积分价值。

| 类别 | 试点建议 | 目的与边界 |
| --- | --- | --- |
| 常规知识库 / 规则 / 浏览 | 不设每日额度 | 保证知识分享与公平 |
| 云端 GPU 预览、转码、素材生成 | 可在测试期限制并发/分钟数 | 控制算力预算，显示剩余次数和重置周期 |
| Arena 练习室 | 每人每日 1–2 次预约、每次 10 分钟（仅示例） | 避免一个人占用共享实时服务 |
| 上传/作品提交通道 | 限文件大小/次数，允许替换草稿 | 防滥用；已提交作品不可无提示改写 |
| 活动挑战 | 每天提供 1 个可选挑战，允许周末集中完成 | 控制一次注意力负担，而非制造连续签到焦虑 |

**公平性要求**：配额不能购买成比赛优势；临时断线要能恢复；无障碍需求和技术问题保留人工处理；不要求每天上线才可继续比赛。

## 07. 赛事业务对象与权益

- Event / Edition：本届赛事 ID、赛制版本、举办单位、时间/场地（待定）、报名与发布状态。
- Challenge / Resource Pack：任务、规则、素材来源、许可、截止时间、支持设备与版本。
- Participant / Team / Entry：身份引用、参赛角色、队伍、提交版本、同意发布的范围。
- Trial Result / Ability Evidence：具体试做的证据、评审人、条件、结论（不等于正式认证）。
- Match / Judging / Appeal：对局、评审依据、投票限制、回放证据、申诉与修正。
- Pass Artifact：活动纪念、作品、参与/能力记录的可分享摘要；默认私人或经本人明确许可。
- Venue Node：场地被授权的节点、控制范围、值班人、故障停机方案、来源。
- Quota Ledger：限额的分配/使用/退回记录；仅当真实共享资源存在时引入。

**版权与隐私**：作品、音乐、视频、视觉素材的展示、评审、存档和二次传播分别征得许可；不默认参赛作品可用于商业推广。举报、撤展、未成年人保护、赞助披露、奖项税务/活动规则在正式报名之前确认。

## 08. 从概念到第一届测试（建议，非既定排期）

- Phase A：以 6–12 名受邀者模拟一轮**完全异步的 45 秒主题作品赛**；使用现有 VIRTURA ID、单独赛事页面、人工分组和可下载素材。检验参赛者能否自己理解规则并提交有效作品。
- Phase B：加入在线 Jam Room / 小型直播评审；检验报名、评审分歧、素材授权、远程回放和网络恢复。
- Phase C：仅在场地、导演、赛务、屏幕/播控、法务及资金确认后举办正式线上/线下联动赛事。
- Phase D：证明已连续运营过两届后再考虑赛事 API、XR 现场节点或更丰富的多人实时游戏层。

**单次会话规则**：每次只给一个推荐动作；任务长度、完成条件、失败后的继续方式清晰；未完成可返回；不出现无限技能树和满屏未开放任务。

## 10. 尚未决定的问题

- 本届主题、地点与时间？线上为主还是线下为主？具体谁负责赛务和安全？
- 直播音频、转播与参赛作品是否已经得到使用授权？远程选手使用何种标准输入与反馈延迟？
- 赛道是混合软件还是统一工作站？用什么证明“实时表演”而非预渲染回放？
- 资格测试与赛事评分是否完全分开？谁制定标准、处理申诉和舞台故障？
- 预算、赞助和奖品能否兑现？如何保护未成年人及观众隐私？
- 用户期望的“入侵现实”体验究竟是**叙事/视觉概念**，还是需要开发真实 QR/AR 场域交互？两者成本差别很大。

## 11. 当前结论与第一动作

本概念先作为 **future product / event concept** 入库；不发布“立即报名”“领取正式驾照”或“奖品已确定”入口。第一动作不是建完整赛事平台，而是制作一张可用的 **Battle Briefing + 45 秒作品试赛**，拿 6–12 人进行首次可用性和规则公平性验证。所有新能力复用 VIRTURA ID、资源/作品对象与可撤销权限，不创建影子身份系统。
